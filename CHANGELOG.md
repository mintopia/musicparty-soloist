# Changelog

## Unreleased — Web UI & config overhaul

### Breaking changes

- **Environment configuration is removed.** The Config File is now the single source of
  truth (ADR-0010): no `${VAR}` interpolation and no environment overrides. Every value is
  read literally from the YAML file. All the previous config env vars are gone —
  `SOLOIST_API_KEY`, `PROXY_TOKEN`, `SOLOIST_DEVICE_NAME`, `AUTOPLAY`, `WEBHOOK_URL`,
  `WEBHOOK_SECRET`, `WEBHOOK_DELAY_MS`, `SNAPCAST_STREAM`, `PROXY_LISTEN`,
  `SOLOIST_DATA_DIR`, and `SOLOIST_PROXY_CONFIG`.

  **Migration:** move those values into the Config File (`config/config.yaml`, bind-mounted
  at `/config/config.yaml` in Docker) — by hand or via the new web UI. `.env` /
  `.env.example` are no longer used and have been deleted. `docker-compose.yml` now
  bind-mounts `./config` instead of reading an `env_file`; the file is seeded from
  `config.example.yaml` on first boot.

  Two infrastructure paths are still read from the environment (they were never part of the
  removed config layer): `SOLOIST_CACHE_DIR` and `SOLOIST_DOWNLOAD_BASE`.

### Added

- **Web UI** served by the Proxy on port 8687: a first-run **Setup Page** for web
  credentials, an authenticated **Landing Page** to edit the whole config, view live
  playback and webhook status, manage Audio Outputs, and restart Soloist.
- **Lyrics Overlay** at `/overlay` — an unauthenticated, observe-only page (uses the
  Read-only Token, embedded server-side) for OBS/browser sources.
- **Config-driven Audio Outputs** (ADR-0011): the Proxy owns the PipeWire fan-out and links
  the captured audio to the outputs you enable, with Snapcast as a toggleable output.
- Autogenerated secrets (`session_secret`, `proxy.token`, `readonly_token`) are minted and
  persisted into the Config File on first boot if left empty.

### Notes

- No built-in TLS — terminate HTTPS at your own reverse proxy if you expose the UI beyond
  the LAN.
